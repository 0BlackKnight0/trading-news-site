# Session summary — "Since" watchlist rebuild

**Dates:** 2026-09-05 → 2026-09-06 · **Repo:** `0BlackKnight0/trading-news-site` · **Branch history:** `feat/smart-watchlist` → `master`, `feat/news-feed` → `master`

## Goal

CODE 2026 brief: *"Build a Smart Market Watchlist"* — users create/manage a watchlist, view market data, **return later and see what changed**. Judged on: what counts as a meaningful change, what info to surface, state persistence, handling stale/conflicting data, scaling, simplicity tradeoffs. End-to-end, no prescribed UI — explicitly *"don't build the obvious watchlist."*

**Starting score: ~3.4/10 as code, ~2/10 live** — the "return and see what changed" requirement (30% weight) scored 1/10: no mechanism existed. Production also 500'd on every Supabase route (root cause found later: the Supabase project had been deleted).

## The product decision

Reframed the watchlist from a **scoreboard** (all rows, always visible, equal weight) to a **changelog** (an event log with a divider marking where the user stopped reading — "Since"). A more ambitious weighted "Signal Score" concept was designed, then explicitly parked as too complex for the timeline.

**Core mechanic:** four pure threshold detectors (`BIG_MOVE`, `VOLUME_SPIKE`, `RANGE_BREAK`, `GAP`), each measured against **that symbol's own average daily range** — not a flat percentage — so the same threshold means something different for a bank and a mid-cap coin.

Docs: [`specs/2026-09-05-smart-watchlist-design.md`](specs/2026-09-05-smart-watchlist-design.md), [`plans/2026-09-05-the-line-phase1.md`](plans/2026-09-05-the-line-phase1.md).

## Phase 1 — "The Line" (event changelog)

Executed via `subagent-driven-development`, 13 tasks in parallel waves, controller-only git (no subagent ran git). **40 → 121 backend tests.**

**Schema:** `price_snapshots`, `symbol_stats`, `events`, `users`, `user_state`, `user_symbol_state`; `watchlist` made per-user.
**Backend:** `signals/` (pure detectors + stats), `pipeline.py` (orchestration), `identity.py` (device-key auth), `routes/feed.py` (`GET /feed`, `POST /feed/seen`), `scripts/backfill.py`.
**Frontend:** `Feed.tsx`, `EventRow.tsx`, `Divider.tsx`, priced watchlist rows with age labels.

**5 real bugs caught mid-build** by subagents/reviewers, all fixed and verified:
1. `vol_30d` sliced two arrays that collapse to the same list under 31 bars → volatility always 0.
2. `close/prev_close - 1` → float cancellation gave `2.0000000000000018` at an exact 2× threshold, firing events the rule should exclude.
3. Same bug in `GAP` (found via a 200k-sample sweep) — `VOLUME_SPIKE` deliberately left alone, sweep proved it isn't the same bug.
4. `fetch_bars` raised instead of returning `[]` when Yahoo's `quote` is `[None]` (truthy, bypassed the `or [{}]` guard) — would have killed a whole batch refresh on one bad symbol.
5. Feed cursor keyed on `occurred_at` alone — verified live that every NSE symbol shares an **identical** timestamp per session, so ties are the norm, not an edge case. Fixed with composite `(occurred_at, id)` cursor.

**Whole-branch review (Opus) then found what no per-task review could see** — every task was individually correct, but:
- `pipeline.py` had **zero importers**. Nothing in production would ever have written an event; the feed would have been empty forever.
- `/feed` had no symbol filter — every user saw every other user's events.
- `insert_news` vs. the new `UNIQUE(url)` index would `23505` and silently drop every news batch, forever.
- `get_or_create_user` raced itself on a new user's first load (Sidebar + Feed mount concurrently).
- Unread was counted on `occurred_at` (constant all day per symbol) instead of `created_at` — an intraday detection could sort *before* the user's baseline and never register.
- 52-week-high claims were possible on symbols with <200 bars of history (false claims from a 3-month fetch window).

All fixed. Merged to `master` via `finishing-a-development-branch`.

## Phase 2 — improved news feed

Spec: [`specs/2026-09-05-news-feed-design.md`](specs/2026-09-05-news-feed-design.md), plan: [`plans/2026-09-05-news-feed.md`](plans/2026-09-05-news-feed.md). User picked all four improvements + tabbed layout (News default, Changes with badge).

**Audit found:** 4 of 9 RSS feeds dead/blocking (both Reuters domains, Moneycontrol 403, VentureBeat 429); only `trading` had a relevance filter, so `tech`/`energy` had **none** — root cause of `Bringatrailer.com` under "energy" and Comic Book Movie under "tech" in production.

**Design error caught mid-build, live:** the spec assumed Yahoo's per-symbol search endpoint resolves entities (it's what `routes/ticker.py` uses). Live testing during implementation proved it returns a **generic finance feed** — `RELIANCE.NS`, `TCS.NS`, `INFY.NS` all returned byte-identical articles about annuities and Nepal floods, 0% about the company. Stopped mid-plan, rewrote spec §4: match the ~60 articles already fetched per refresh against company-name aliases from Yahoo's `meta.longName`, zero extra API calls, degrades to *empty* rather than *wrong*.

**Second bug, also caught against live data:** the bare alias `reliance` (ordinary English word) matched *"reduced reliance on the US dollar"* in an unrelated story. Fixed with an ambiguity denylist — common-word aliases dropped unless dropping would leave a symbol with none.

**Measured real coverage: 3 of 122 stored articles mention a watchlist company (~3%)** — low, but zero false positives after the fix. Stated cost of "never wrong, sometimes sparse."

Also shipped: dead feeds removed, `tech`/`energy` relevance filters added, source denylist, `NULLS LAST` ordering fix, 30-day retention, transparent integer article scoring, News/Changes tabs, separate `news_last_seen_at` baseline.

**121 → 198 backend tests.** `feat/news-feed` verified (tsc clean, build ok), merged to `master`.
